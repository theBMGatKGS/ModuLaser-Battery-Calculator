# Changelog

All notable changes to the ModuLaser Battery Calculator are documented here.

Format: `MM.mm.rrr` (major.minor.patch), date `YYYY-MM-DD`. Major and minor
versions are set manually; patch numbers increment per distinct logical change

## 01.05 — 2026-10-02

- **01.05.009** (2026-10-02): Fixed tall custom calc-select menus (Fan Speed, Addresses, and any other long list) that could not scroll: a capture-phase window scroll listener was closing the menu on the list's own scrollbar drag and mouse-wheel scroll. Listener now ignores scrolls that originate from the open list; outside-click dismiss also treats pointer-down inside the open list's bounding box as inside; option commit moved from mousedown to click and lists use scrollbar-gutter:stable so scrollbar/gutter drags are not stolen by option hit-targets (overlay scrollbars). Also added keyboard navigation while a menu is open — Arrow Up/Down, Page Up/Down, Home/End move the highlight (with scroll-into-view), Enter/Space commit, Escape closes — and stopped ArrowDown on the closed-state button from toggling an already-open menu shut.

- **01.05.008** (2026-10-02): Sheet header layout: Power Supply Name and Location now occupy a full row above Design Basis / Standby / Alarm / Ambient Temperature (previously side-by-side with those controls, so long PS titles encroached on the Design Basis dropdown). Design Basis control widened (flex min ~400px) so the full selected label shows for every preset — including NFPA 72 + NFPA 110 Generator Backup (Non-Voice/Voice) — without truncating into adjacent fields. Custom calc-selects, needs-entry, save/load, and print unchanged.

- **Release tagging** (2026-10-02): GitHub desktop releases now use tag **v01.05.007** matching calculator revision **01.05.007** (date suffix `_261002` remains in-app only). This supersedes the separate `v1.0.x` installer numbering for the same build; older `v1.0.x` tags stay as history. npm/`electron-builder` package version is semver `1.5.7` (no leading zeros); Windows installer asset is `ModuLaser.Battery.Calculator.Setup.01.05.007.exe`.

- **01.05.007** (2026-10-02): Replaced unreliable native <select> option popups (Chromium/Electron still painted light OS menus with light text despite 01.05.006 CSS) with custom white-on-black listboxes for all calculator selects — Addresses, Module Types, Design Basis, Ambient Temp, Fan Speed, and the rest. Native selects stay in the DOM (visually hidden) so value/change/save-load/needs-entry/validation keep working; open menus use fixed positioning to escape .location overflow clipping. Verified open menus via browser screenshots.
- **01.05.006** (2026-10-02): Fixed native <select> dropdowns (Addresses, Module Types, Design Basis, Ambient Temp, Fan Speed, and other selects) that rendered white text on white background in the open option list — forced white text on black background for select and option elements, plus color-scheme:dark for Chromium/Electron/Safari native popups. Needs-entry soft blue chrome, yellow validation, and red invalid styles unchanged.
- **01.05.005** (2026-10-02): Added searchable How Do I… in the main toolbar and Help overlay: type-ahead filters curated common topics plus other Help/FAQ/Quick Start entries, shows a short inline answer with a jump link into the full Help section.
- **01.05.004** (2026-10-02): Quick Start updated with steps 13–16 documenting blue needs-entry highlights, Confirm defaults, Clear (sheet vs entire file), and Import Calc (replace/merge, collision choices, older-revision warning), each with qs-figure wireframes.
- **01.05.003** (2026-10-02): Date field excluded from needs-entry (blue) highlighting; new/cleared documents still initialize Date to today, and the field remains normally editable afterward.

## 01.04 — 2026-08-10 to 2026-09-03

- **01.04.008** (2026-09-03): Added a Module Current Draw Reference table to Standards and Formulas, per Brent: every module's current draw as used by this calculator (24V) alongside the manufacturer's 18V figures for cross-reference, sourced from Brent's uploaded worksheet image. Display rows use the TFT-On/LEDS-On (highest-draw) state per Brent's explicit choice; two real data gaps in the source (no LEDS-On figure for Minimum Display, no separate Command Display entry at all) are documented inline via numbered footnotes rather than silently guessed at. Detector rows reuse the calculator's own FAN_SPEED_MA constant for the 24V column (a new companion FAN_SPEED_MA_18V constant holds the reference-only 18V figures) so the embedded table can never drift from the actual calculation logic. Also shipped as two standalone reference files (Excel + HTML, styled to match the calculator) alongside the three calculator deliverables.
- **01.04.007** (2026-08-18): Fixed a real startup/restore bug: opening a saved file could show a false "address not assigned" INVALID CALCULATION banner even though every address was correctly saved and restored. Root cause: the invalid-calculation check ran before the address dropdowns' deferred restore values had been resolved into real selections, and nothing re-checked afterward. Fixed with a second pass after restore, once addresses are fully resolved. Also updated Quick Start's cluster-building step to describe the new same-sheet ribbon capability for remotely-referenced detectors.
- **01.04.006** (2026-08-18): Fixed three real bugs Brent hit in actual use, all reproduced directly before fixing. (1) Circuit source: selecting an AUX Circuit # never filled in the separate Circuit Source text field the validation actually checks, so a properly-assigned entry point could still show "missing circuit source" — now auto-populated from the PS name + assigned circuit number, tracked the same way as other auto-vs-manual fields so a deliberate custom entry is still respected. (2) Detectors that both reference the same remote cluster (cross-sheet, display-less) could never ribbon-connect to each other — the code explicitly treated any remote reference as own-circuit-only; fixed so ribbon, being a physical/per-sheet concept, works locally between same-sheet detectors sharing a remote cluster reference, independent of whichever sheet hosts that cluster's display. (3) The ribbon segment-count validation and the auto-reorder-on-sheet logic both only scanned locally-hosted clusters, so a display-less sheet's ribbon segments were silently never validated or grouped — both fixed to scan every cluster the sheet actually touches.
- **01.04.005** (2026-08-10): Reviewed and expanded Quick Start end to end, per Brent. Added a new step 6 (Choose Networked or Standalone addressing), positioned right after the Address step per Brent's explicit placement instruction, renumbering the remaining steps 7-11. Also closed three gaps found during the review that predated features now in the calculator: expanded the cluster-building step to cover Command Displays (a real module type that was never mentioned anywhere in Quick Start), and added a new final step 12 covering Save As, Autosave, and Export to Excel — none of which were documented, despite all three being real toolbar features. Verified autosave's actual mechanism (browser localStorage, not portable) and Excel export's actual output (one worksheet per power supply) directly in the code before describing them, rather than assuming. Fixed a stale internal step-number cross-reference this renumbering would otherwise have broken.
- **01.04.004** (2026-08-10): Added FAQ documentation for the new Standalone / Networked toggle, and updated the granular calculation detail FAQ entry to mention the new per-module current listing.
- **01.04.003** (2026-08-10): Found and fixed a real bug while building the Standalone addressing scope: cluster numbers turned out to only be unique within their own sheet (confirmed by reading the actual auto-assignment code), not document-wide as initially assumed — meaning two completely unrelated clusters on different sheets can share the same bare number. Grouping Standalone addresses by that bare number alone would have wrongly treated them as one cluster. Fixed by keying on the cluster's true (host sheet, cluster number) identity instead, resolved the same way cross-sheet references already resolve it — verified via test that two unrelated same-numbered clusters no longer conflict, while genuinely cross-referenced clusters correctly do.
- **01.04.002** (2026-08-10): Added a per-sheet Standalone / Networked addressing toggle, per Brent (clarified via 3 follow-up questions before building): Networked (default, for both new sheets and legacy saved files) is unchanged — Address stays a 1-127 dropdown, unique network-wide. Standalone gives a cluster with no SenseNET pathway a 1-9 dropdown, unique only within that specific cluster; a different, unrelated cluster elsewhere can freely reuse the same addresses. Multi-cluster sheets keep independent 1-9 pools per cluster even in Standalone mode; Cluster identification stays fully enforced either way; cross-sheet cluster referencing keeps working normally regardless of either sheet's scheme, per Brent's explicit confirmation.
- **01.04.001** (2026-08-10): Minor version bumped to 01.04 per Brent; revision counter restarted at 001. Added granular per-module current to the Calculation Detail panel's Module & Supply Load section — every module on the sheet now lists its address, model, and current draw individually (visually separated from the Displays/Detectors subtotals by a dashed divider), not just the aggregated totals. Verified per-module figures sum exactly to the existing subtotals, and confirmed via print render that it still fits cleanly alongside the rest of the detail page.
